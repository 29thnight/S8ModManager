# 도시 AI 출진 요청 검증 (2026-11-05)

## 기준과 이름

게임 분석 대상은 `SAN8RPK.exe.unpacked.exe`, SHA256
`f47c1112dfa1fa4067fde43ad2e4fd906bbba341d47fda4f6ef1724be4df43c1`이다.
REA 6.8.0 / Ghidra 12.1.4의 `rea-march-followup-13.json`에 보존한
`0x145A6B0` 전체 어셈블리와 의사 코드를 대조했다.
도시 AI 출진, 편성, 실행이라는 역할명은 분석자가 붙인 이름이다.

- 기존 ABI·컴포넌트 검사 140개 통과. 실제 출진 시험과 별개의 검사다.
- 설치 파일 해시 일치 및 실행 프로세스의 S8.Scripting.Native.dll 적재 확인.
- `MarchExecutionProbe.cs`는 enabled 파일이 있을 때만 주인공에 붙는다.
  arm 파일 한 개를 사용 완료 파일로 옮기고, 세션당 한 번만 아군 도시의 공격 후보에 요청한다.
  매 프레임 조회나 실패 재시도는 없다.
- 손상향 수동 슬롯 30, 212년 7월 평정: CouncilEntered에서 도시 30→29 요청.
  이후 보수 완료 콜백에서 `RejectedByGame`, 원본 반환 0을 C#으로 읽었다.
  이 첫 호출의 구체적인 거절 분기는 계측하지 않아 확정하지 않았다.
  같은 슬롯을 다시 불러온 시험에서는 `145B265`의 JLE가 실제로 선택됐다.
  이때 설정 확률 EBX=0x32(50), 원본 난수 EAX=0x46(70)이므로 `50 <= 70`으로 거절됐다.
  편성·군량 검사를 통과한 뒤 중간 전력 구간의 AI 확률 판단에서 포기한 사례다.
  이 결과를 첫 호출의 난수 값으로 소급하지 않는다.
- 손상향 수동 슬롯 32, 212년 5월 도시: 보수 완료에서 도시 34→33 요청.
  네이티브 영수증이 Executing인 동안 원본 래퍼의 145B31A에서
  `CALL 194A050`에 도달함을 확인했다. 중단점은 제거하고 디버거를 분리했다.
  게임에서 양양의 관우 측이 신야로 출진했다는 알림과 유비군의 신야 점령 알림을 확인했다.
  후처리 종료 후 다음 보수 완료에서 C#이 `Invoked`, 원본 반환 1을 회수했다.
  이후에도 성문 메뉴에서 정상적으로 조작할 수 있었다.
- 시험 후 손상향 평정 슬롯 30을 다시 불러온 상태로 두었다. 수동 저장하지 않았다.
  테스트 enabled 파일은 분석 폴더로 옮겼고 arm 파일은 소비됐다.
  계측 중단점을 제거하고 디버거를 분리했다.

## 검증의 범위

### 월 변경 실행 추가 시험

- `MarchExecutionProbe.cs`에 선택적인 `march-probe.month-only` 모드를 추가했다.
  새 요청은 MonthChanged에서만 제출하며, 이미 제출한 요청의 결과는 후속 내정/평정에서도 읽는다.
- GameScripts만 Release 증분 빌드했다(경고 0, 오류 0). 설치 DLL 해시가 일치했다.
  실행 중 기재 편집 메뉴의 Configure 경로로 JIT 재로드했다. 네이티브 DLL은 변경하지 않았다.
- 손상향 슬롯 32의 212년 5월 도시 세이브에서 휴양했다.
  02:16:07, session=8, `boundary=month.changed source=34 target=33 status=Queued` 한 건을 기록했다.
  게임에서 양양 관우 측의 신야 출진, 두습 측 요격, 유비군의 신야 점령, 여건 등용 알림을 확인했다.
- 6월 도시 화면으로 돌아온 뒤 보수를 실행했다.
  02:20:03, 같은 session=8, `boundary=domestic.completed source=34 target=33 status=Invoked nativeReturn=1`을 회수했다.
  요청 생성은 한 번이며 후속 콜백에서 추가 출진하지 않았다. 이번 시험에는 디버거를 붙이지 않았다.
- 시험 후 enabled/month-only 파일을 분석 폴더로 옮겨 비활성화했다.
  수동 저장 없이 슬롯 32를 다시 불러와 시험 전 도시 상태로 복귀했다.

평정 진입 요청의 거절 결과 전달, 내정 완료와 월 변경 요청의 실제 실행 경로는 확인했다.
주인공 직접 참전 전환, 세이브/로드 후 전투 유지,
모든 거절 분기의 개별 실행 시험은 아직 하지 않았다.
`Invoked`는 원본 래퍼 반환을 뜻하며 일반적인 승리 보장은 아니다.

### 전투 조작 확인 누락 — 판정 정정

사용자가 이 상황에서는 원본 게임이 전투를 조작할지 반드시 물어봐야 한다고 확인했다.
따라서 위 시험은 출진 호출·점령·반환 전달만 확인한 것이며, 정상적인 플레이어 출진 흐름 통과로 판정하지 않는다.
전투 조작 선택 누락은 미해결 사항이다. 방어 평가 1만으로 확인창 생략을 정당화할 근거는 없다.
저장된 EXE 디컴파일의 194A050에는 주인공 및 참여 조건에 따른 1927020 호출과
이후 별도의 전투 처리 분기가 있다. 1927020이 해당 확인창인지, 이번 호출이 어느 조건에서
이를 건너뛰었는지는 아직 확정하지 않았다. 원본 UI 출진과 스크립트 출진을 같은 세이브에서
비교 계측해 선택창 경로와 인자를 확인해야 한다.
