# 분기 평정 + 월간 상신 시제품

## 현재 연결

`CouncilStrategySetup`이 세션 주인공 GameObject에 `CouncilStrategyComponent`를 추가한다.
원본 평정 일정은 변경하지 않는다. 1·4·7·10월의 확인된 `CouncilEntered`에서
`QuarterlyCouncil`을 알린다. 입장 연출 이전의 이벤트가 아니다.

월 변경에서 전체 51개 도시를 한 번 평가한다. 확인된 내정 완료 이벤트에서는
활동 장수의 소속 도시만 평가한다. 현재 이 내정 이벤트는 성문 보수로 확인된 범위다.
프레임 업데이트, 타이머, 백그라운드 메모리 수집은 사용하지 않는다.

플레이어 세력 도시는 기본적으로 자동 출진하지 않는다. 다른 세력은
원본 후보 검사에 통과한 인접 도시 중 방어 추정치가 가장 낮은 곳에 출진 요청한다.
도시별 월 1회만 실행을 시도하며 원본 AI가 거절해도 같은 달 재시도하지 않는다.
기존 게임 AI는 그대로 동작한다. 이 월간 경로는 기존 AI를 대체하지 않고 추가한다.

원본 출진 래퍼가 편성·실행 가능 여부·비용·참전 및 전투 조작 질문을 처리한다.
`Completed`는 출진 요청 결과를 회수했다는 뜻이다. 실제 출진 여부는
`Result.WasInvoked`로 구분한다. 전투 종료 또는 승리를 뜻하지 않는다.

## 상신·결재·위임 API

```csharp
var strategy = world.GetPlayer().Character.GetComponent<CouncilStrategyComponent>()!;

// 월 변경 또는 평정 진입 이후의 게임 콜백 안에서 호출한다.
var proposal = strategy.SubmitMarch(officerId, targetCityId);
strategy.Decide(proposal, governorId, approve: true);
// 보류: approve: false, defer: true / 거절: approve: false

// 목표/권한은 스크립트의 평정 정책에서 설정한다.
strategy.SetCityOrder(cityId,
    new CityStrategyOrder(CityStrategyGoal.LimitedOffensive, DelegateMarch: true,
        TargetCityId: targetCityId));
```

상신은 소속 도시·세력이 있는 장수당 월 1건이다. 결재자는 현재 도시의
태수 또는 군주여야 하며, 상신 당시 세력과 현재 도시 세력이 일치해야 한다.
승인해도 도시당 월 1회 제한과 진행 중 요청 중복 방지를 적용한다.
위임 목표는 도시 세력이 바뀌면 해제한다. `Rebuild`, `Defend`는 이 추가 경로의
출진을 중지한다. 원본 AI의 수비·복구 정책을 변경하는 명령은 아니다.

`ProposalChanged`로 접수/결재/실행 결과를 관찰하고 `Proposals`로 목록을 조회한다.
상신 선택창과 결재창은 아래 C# 메뉴 구현으로 연결했다. 해당 UI의 빌드·게임 시험은 아직 하지 않았다.

## 추가 조사 및 대기열 예외 검사

시작 충돌은 11월 4일 15:57의 PID 28360 덤프에서도 같은 메모리 풀 해제 함수
`0x772780` 안의 `0x7727F9`에서 발생했다. 11월 5일 PID 12728의 `0x77286C`와
상위 호출 `0x1D184F0 → 0x17F06DD`를 공유한다. 이번 전략 대기열 수정 이전에도
같은 종류의 손상이 존재했다는 증거이며, 원본 게임만의 결함이라는 증거는 아니다.

집중 역분석에서 `0x772780`은 빈 메모리 블록을 합치고 연결 목록에서 제거하는
처리이고, `0x17F05B0`은 여러 직렬화 버퍼를 하나로 복사한 뒤 이전 버퍼들을

PE의 chained unwind 조각을 합쳐 함수 범위를 잡았다. 조각만 역컴파일한 출력은
입력 레지스터를 놓치므로 최종 근거에는 `ghidra-full-*.c`를 사용한다.

치명적 예외만 포착하도록 디버거를 연결한 시작 시험 2회에서는 재현되지 않았다.

## 세이브별 전략 상태 (2026-11-05 실행 검증)

`GameWorld.SaveData.Get<T>(key)` / `Set(key, value)`는 모드별 이름을 붙인 JSON 값을
네이티브에 전달한다. `Set`은 메모리에 저장할 스냅샷을 준비하며 디스크 저장을 직접
실행하지 않는다. 게임 저장이 완료되면 원본 파일 옆의 `.s8mods` 파일에 기록한다.
원본 게임 파일 형식은 바꾸지 않는다. 전체 모드 상태 상한은 1 MiB다.

- 저장 시작 `0x16D0270`: 준비된 JSON 복사. 지연 저장도 이 복사본 사용.
- 저장 확정 `0x16D04C0`: 원본 함수가 성공한 경우 게임 파일과 JSON의 SHA-256을
  함께 기록하고 임시 sidecar를 최종 파일로 교체.
- 로드 `0x16CCC70`: 원본 로드가 성공한 뒤 크기/형식/두 해시가 일치하는 상태만 복원.
  경로는 원본 호출 전에 복사하므로 archive 정리 이후 문자열 수명에 의존하지 않는다.
- 시나리오 초기화 `0x16E6860`: 전역 루트 교체 진입 시 이전 모드 상태 해제.
  이후 디스크 로드가 있으면 해당 파일 상태 설치.

이 RVA의 이름은 역분석에 붙인 설명이다. 저장 작업 스레드에서는 CLR에 진입하지
않고 C++이 복사된 문자열만 다룬다. 파일 처리는 저장/로드 경계에서만 수행한다.

전략 컴포넌트는 날짜, 도시별 목표·위임과 소유 세력, 월별 제출·출진 시도 기록,
상신 목록과 완료 결과를 저장한다. 포인터·출진 티켓·콜백은 저장하지 않는다.
`Submitted` 기록은 복원 시 `Interrupted`로 바꾸며 자동으로 다시 출진시키지 않는다.
JIT 재로드에서도 티켓을 다시 연결하지 않으므로, 이미 네이티브 큐에 제출된 요청이
취소되는 것은 아니다. 이 상태는 추적 연결 중단을 뜻한다.

로드 세대가 바뀌면 같은 epoch라도 월드를 다시 구성하고 이전 `SaveData` 참조를
무효화한다. sidecar가 없거나 파일 해시가 다르면 빈 모드 상태로 시작한다.
해시를 통과했더라도 JSON/전략 스키마가 지원되지 않으면 해당 설정 초기화를 거부한다.
게임 파일과 sidecar 두 파일의 교체는 하나의 트랜잭션이 아니다. 중간 종료로 해시가

### 특권 건의와 상급자 대화 연결 (소스 구현, 미빌드)

집중 분석으로 0x17275E0이 주인공 특권(root+0xEA)을 1개 소비하고 사용 횟수(root+0x5C08),
알림 및 실적 처리를 갱신하는 것을 확인했다. 직접 메모리 차감 대신 이 함수를 호출한다.
0x192A140은 전략 포인트·명령 상태도 변경하므로 단순 특권 소비 함수로 사용하지 않는다.
분석 파일: ghidra-privilege_17275e0.c, ghidra-privilege_192a140.c, ghidra-privilege_189f380.c.

- Player.Resources.Privileges, CityAiComponent.RequestPrivilegedMarch,
  CouncilStrategyComponent.SubmitPrivilegedMarch를 추가했다.
- 대상 선택 후 일반 상신과 특권 건의를 구분한다. 특권 건의는 특권이 있고,
  자신과 다른 태수 또는 군주가 있으며 해당 도시의 월별 출진 요청 제한에 걸리지 않을 때 표시한다.
  나머지 경우 확인 화면 제목에 특권 없음/결재 대상 없음/기존 출진 요청 등의 이유를 표시한다.
- C#에서 건의자가 특권 출진을 건의하고, 실제 소속 도시 태수가 승인 대사를 한다.
  태수가 없거나 자신이 태수이면 자기와 다른 소속 군주를 대화 상대로 사용한다.
  원본 AF530 대화 API로 초상화를 표시하되 대사 문구는 이 모드가 작성한 것이다.
  원본 평정의 승인 대사 메시지 ID나 승인 안건 상태 머신을 재사용한 것은 아니다.
- 대화 후 Pending 결재 대기를 생성하지 않고 Submitted 요청을 등록한다.
  네이티브가 요청에 저장하는 것은 세션·도시·주인공·결재권자 ID이며 포인터를 저장하지 않는다.
- 0x1600E60 도시 명령 UI 업데이트의 원본 호출 이후 명시적 특권 요청이 있을 때만 큐를 처리한다.
  확인창이 남아 있으면 기다린다. 기존 AI 큐를 이 업데이트에서 실행하지 않는다.
  특권 요청 유무는 atomic flag로 확인하며 도시·장수의 주기적인 전체 스캔을 추가하지 않았다.
- 실행 시 소속 도시·양측 세력·인접성·공격 대상 자격·현재 주인공·실제 결재권자·특권 수량을 확인한다.
  특권 부족 또는 결재권자 변경은 별도 완료 상태로 취소한다. 이때 특권을 소비하지 않는다.
- 허용되면 원본 특권 소비를 1회 호출하고 기존 0x145A6B0 출진 래퍼로 진입한다.
  소비 후 원본 래퍼가 편성 등의 이유로 거절하면 특권을 돌려주는 처리는 없다.
  원본 래퍼 내부의 편성·전투 조작 확인·출진 결과 반환은 기존 경로다.

이 구현은 소속 도시 태수/군주 관계를 사용하는 모드의 특권 승인 정책이다.
도독의 군단 전체 권한, 두령의 방랑군 권한, 원본 안건별 모든 신분 제한은 아직 연결하지 않았다.
날짜를 진행하지 않는 평정 연출·하단 메뉴, 원본 도시 일람·지도 선택 화면과 이름 조회도 남아 있다.

자동 검사 소스에 건의자→실제 상급자 발화 순서와 전용 특권 요청 전달을 추가했다.
이번 요청은 소스 구현 범위로 진행했으며 빌드/검사 실행/배포/게임 특권 소비 시험은 하지 않았다.
재컴파일 범위는 script_api.h를 참조하는 네이티브 프로젝트와 SDK/Host/GameScripts다.

### 월간 상신 UI 후속 연결 (소스 구현, 미빌드)

- 상신 허브, 특권 확인, 결재 방침, 도시 목표 선택을 공통 `ChooseMenu`로 연결했다.
  기존 원본 Form 팝업의 버튼과 설명 텍스트를 사용한다. 평정 장면이나 하단 메뉴를 연 것은 아니다.
- `UiRow.Enabled`와 `DisableDialogRow`를 추가했다. 사용 불가 항목도 이유와 함께 남기며,
  네이티브 버튼의 활성 상태를 끄고 클릭 콜백도 차단한다. 모달 초기화 전 요청도 프레임에 보관한다.
  행의 네이티브 구조 크기는 바꾸지 않았다. 이 기능은 Form/CompactForm에서 제공한다.
- 허브에 태수·군주 관계, 특권 수량, 이번 달 상신 여부를 표시한다.
  결재·도시 목표는 현재 구현된 태수·군주 지휘 범위에 따라 비활성화한다.
  도독·두령 등의 원본 전체 권한을 판정하는 API는 아직 구현 전이다.
- 대상 선택 취소는 허브로, 상신 확인 취소는 대상 목록으로, 결재·도시 목표 완료는 해당 목록으로 돌아간다.
  특권 승인 대화와 출진 요청 등록 경로는 유지한다.
- `StrategyPhaseGameState`와 `ConferenceMainCommandState`에는 실제 월·명령 처리가 섞여 있다.
  해당 상태를 월간 화면으로 직접 실행하는 코드는 추가하지 않았다.
  원본 지도 레이아웃 초기화/선택 콜백을 분석했지만 구성·소유권·해제 경로의 연결은 남아 있다.

남은 UI: 날짜를 진행하지 않는 평정 입퇴장 연출·하단 메뉴, 원본 도시 이름 조회,
도시 일람·상세 및 지도 강조 선택. 이 항목들은 이번 수정으로 완료되지 않았다.
빌드·자동 검사·게임 적용·화면 검증은 실행하지 않았다.

### 평정 장면·도시 지도 후속 연결 (2026-11-05, 소스 연결 / 미빌드)

앞 절의 남은 UI 항목에 대해 다음 경로를 추가했다. 아래 내용은 소스와 정적 분석 결과이며
게임에서 표시·클릭·연출·월 불변을 확인한 결과가 아니다.

- `CityComponent.Name` → `ReadCityName` → RVA `0x1704AF0`.
  CityData의 런타임 ID(+8)가 아니라 이름 키(+0xA)에 `0x4A81`을 더해 게임 문자열 표를 조회하는 함수다.
  대상·기록·결재·도시 목표에서 이 이름을 사용한다. 조회는 요청 시점에만 수행한다.
- `WorldEventContext.ChooseCity` → `DialogKind.CityMap`.
  원본 `ConferenceDepartCityDlgState`의 선택 모드 3을 사용한다.
  전용 생성 래퍼는 `0xF3120`이며, `0x5D530`은 PersonalityData 선택 창 전용 생성 래퍼여서 사용하지 않는다.
  선택·후보·보조 목록을 원본 포인터 목록으로 구성하고, 원본 지도·상세 창·도시 일람을 유지한다.
  후보 도시만 허용 목록에 전달하며 출발 도시는 지도 컨텍스트에 지정한다.
  이 선택 상태에서는 출진 실행 함수를 호출하지 않고 선택한 도시 ID만 C#으로 반환한다.
  월간 평정 안에서 열며, 취소 시 원본 지도 애니메이션 종료를 기다린 뒤 선택 상태만 닫는다.
- `ChooseCouncilMenu` → `DialogKind.CouncilMenu` → `monthly_council_ui.inl`.
  생성 래퍼 `0x683BD0`으로 별도 `ConferenceGameState` 인스턴스를 연다.
  `StrategyPhaseGameState`를 실행하거나 정규 평정 종료 상태로 전환하지 않는다.
  원본 인스턴스의 진입·화면 로드·장면 전환 경로를 사용하고, 월간 인스턴스의 명령 상태만 교체한다.
- 정규 명령 진입 `0x1979EA0`에는 세력 계획 정리 등이 있으며, 갱신 `0x19798F0`에는 실제 명령 소비가 있다.
  월간 명령 상태는 이를 호출하지 않고 장면·카메라 갱신만 수행한다.
  정규 `ConferenceExitState` 및 평정 결과 반영 경로 대신 이 화면의 상태만 팝한다.
  실제 연월 필드 `+0x72D0`를 쓰는 코드는 추가하지 않았다.
- 하단 명령 바의 원본 버튼·문자 컨트롤을 사용해 상신·결재·기록·목표·퇴장을 배치한다.
  선택 콜백(+0x2C0)과 도움말 콜백(+0x340)을 분리하고 사용 불가 항목의 설명을 제공한다.
  하위 창이 닫힐 때까지 평정 장면을 유지하고, 허브로 돌아오면 메뉴를 재연결한다.
- 월간 화면이 빌리는 평정 컨텍스트·명령 ID·메뉴 모드·콜백은 퇴장 시 복원한다.
  다른 세션으로 바뀌었다면 이전 데이터와 UI 포인터를 새 세션에 복원하지 않는다.
  개별 인스턴스의 가상 함수 표는 엔진의 모델 파괴가 끝날 때까지 완료 콜백이 소유한다.
  게임의 공유 가상 함수 표와 EXE 파일은 변경하지 않는다.
- 특권 출진은 승인 대화·요청 등록 후 `CloseCouncil()`을 호출한다.
  화면이 완전히 닫혀 `native_ui_active`가 해제된 뒤 기존 도시 업데이트의 전용 큐가 실행한다.

함수의 C++ 이름은 역공학 바인딩 이름이며 공개 SDK 이름이 아니다. 클래스 이름은 RTTI 기준이다.
도독·두령 등 원본 전체 신분 권한 분석은 이번 화면 연결과 별개로 남아 있다.

검토: 변경 diff와 네이티브 생성 래퍼·콜백 인자·객체 수명 경로를 확인했다.
관리 코드 검사 소스는 도시 ID 반환, 비활성 행, 특권 요청 뒤 화면 닫기에 맞춰 수정했으나 실행하지 않았다.
빌드·배포·실행 검증은 하지 않았다. 다음 게임 검증에서는 진입/퇴장 전후 연월, 하단 버튼 클릭/도움말,
지도·일람에서의 같은 도시 선택, 취소 복귀, 다른 주인공·도시, 특권 출진 후 궁성 메뉴 복원을 확인해야 한다.
